# Changelog

All notable changes to **Pregate** are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- The astro pack (1.0.0) checks the TypeScript and JavaScript files Astro reads outside a template. The engine does not parse `.astro` files. `astro/content` warns when a content collection omits its Zod schema (`ASTRO-SCHEMA-001`) and, when the nearest `astro` declaration is entirely 5.0.0 or newer, denies a collection with no loader (`ASTRO-LOADER-001`). Astro 4 `type: "content"` stays quiet. `astro/config` denies a client environment variable marked secret (`ASTRO-ENV-001`) and `output: "server"` with no adapter (`ASTRO-ADAPTER-001`). `astro/routing` denies a middleware module that does not export named `onRequest` (`ASTRO-MW-001`), a lowercase HTTP handler in `src/pages` (`ASTRO-ROUTE-001`), and an action with no handler (`ASTRO-ACTION-001`). `client:*` islands and `server:defer` are in the pack backlog because they live in the template.
- `pregate scan` recommends the Astro pack (`astro/config`, `astro/content`, and `astro/routing`) when `astro` is a dependency or peer dependency of a primary package. A devDependency, a package named `astro`, `astro.config.*`, and a `.astro` file do not. A match that exists only under `docs/`, `examples/`, or `fixtures/` does not either.
- The tanstack-query pack (1.0.0) checks two TanStack Query rules from the [query keys guide](https://tanstack.com/query/latest/docs/framework/react/guides/query-keys) and the [stable QueryClient guide](https://tanstack.com/query/latest/docs/eslint/stable-query-client). `TQ-KEY-001` denies a `queryKey` that is a string, template, number, object, boolean, `null`, or `undefined`, including one wrapped in `as`, `satisfies`, or parentheses. An array key is allowed. `TQ-CLIENT-001` denies `new QueryClient()` inside a synchronous component or hook, and inside a `render` method. A module-scope client, a `useState` initializer, and an async function are allowed. `pregate scan` recommends the pack from `@tanstack/react-query`, `@tanstack/vue-query`, `@tanstack/solid-query`, `@tanstack/svelte-query`, `@tanstack/angular-query`, and `@tanstack/angular-query-experimental` in `dependencies` or `peerDependencies`. A devDependency does not. `@tanstack/query-core` and the devtools packages do not, on their own. Scan treats a `fixtures/` or `fixture/` directory as peripheral, the same way it treats docs and examples, so a dependency that appears only there does not recommend any pack. Query-function dependencies, mutation invalidation, TanStack Start, and TanStack Router are recorded in the pack backlog and are not rules.
- The hono pack (1.0.0) checks Hono apps against the [best-practices guide](https://hono.dev/docs/guides/best-practices), the [middleware guide](https://hono.dev/docs/guides/middleware), and the [factory helper](https://hono.dev/docs/helpers/factory). `pregate scan` recommends `hono/routing` and `hono/middleware` when a package depends on `hono` or lists it as a peer dependency. A devDependency, the package name `hono` by itself, and a different package such as `@hono/node-server` do not. A declaration that exists only under a docs site, examples tree, or `fixture/` / `fixtures/` directory does not either.
  - `HONO-CTRL-001` denies a route whose handler is a name or a method, and a class named `*Controller` with a `Context` parameter. Write the handler inline, spread `factory.createHandlers()`, or mount a sub-app with `app.route()`.
  - `HONO-HEAD-001` denies `app.head` and `app.on('HEAD')`. Hono answers HEAD from the GET handler.
  - `HONO-NEXT-001` denies `next()` without `await` in middleware shaped `(c, next)` or `(_, next)`.
  - `HONO-MW-001` denies that same middleware when it is declared outside `createMiddleware`, `factory.createMiddleware`, `createHandlers`, or an inline `app.use` / route callback.
- Vercel is a CI provider next to GitHub Actions. `pregate install --ci vercel` writes a build recipe that installs the pinned linux-x64 release and runs the gate before the framework build, including on a repository with no Actions workflow. `pregate install --ci github` is unchanged. `pregate install --ci github,vercel` writes both.
- `pregate ci detect`, `pregate ci status`, and `pregate ci wait` read GitHub commit statuses and check runs. Vercel contexts are `Vercel` and `Vercel – <project>` (Ready passes; Error, Canceled, and a missing status do not). A repository that configures both providers must see both pass. A required status that is missing or failing does not pass.
- The [Vercel guide](docs/guides/vercel-ci.md) covers `vercel.json` `buildCommand`, the package script, the build cache, and preview versus production.
- The TypeScript pack reports two removals from TypeScript 7.0. `TS-NS-001` still warns on `namespace`, which remains valid TypeScript. `TS-MODKW-001` reports a namespace written with the `module` keyword (`module Billing {}`, including `export module` and `declare module Billing`). An ambient module (`declare module "pkg"`, `declare module 'pkg'`, `declare module "*.json"`) stays allowed. `TS-MODKW-001` denies the keyword form on TypeScript 7.0.0 or newer and warns on an older or unknown compiler. The repair is to write `namespace`, or to export the values from an ES module.
- `TS-ASSERT-001` denies an import assertion when the project installs or declares TypeScript 7.0.0 or newer: `import rates from "./rates.json" assert { type: "json" }` and `import("./rates.json", { assert: { type: "json" } })`. Write `with` instead. `import ... with { type: "json" }` is allowed. A project on older TypeScript, or with no TypeScript dependency, is not blocked, because `assert` still compiles there. The installed `node_modules/typescript` version wins over the range in `package.json`.
- The node pack (1.3.0) covers three Node.js 26 API changes, and only when the project declares Node.js 26 or newer. `node/NODE-HEADER-001` denies `ServerResponse.writeHeader` (DEP0063, removed; use `writeHead`). `node/NODE-STREAM-001` denies imports of the removed `node:_stream_*` modules (DEP0193; use `node:stream`). `node/NODE-REGISTER-001` warns on `module.register` (DEP0205; use `module.registerHooks`). Pins come from `package.json` `engines.node` and `volta.node`, `.nvmrc`, `.node-version`, and `.tool-versions`. An older pin, a missing pin, or a pin that does not name a version keeps the rule quiet.
- Recursive `fs.rmdir` is not a new rule. DEP0147 reached end of life in Node.js 25.0.0, and the Node.js 26.0.0 release notes do not list it.
- Prisma pack 1.3.0 flags three Prisma ORM 7 client breaks, and only when the nearest package is on Prisma 7 or newer. A Prisma 6 range such as `^6.19.0` stays quiet, including when a sibling has hoisted a newer client.
  - `PRISMA-MIDDLEWARE-001` denies `$use`, including a computed `prisma["$use"]` call. Replace it with a client extension (`$extends`).
  - `PRISMA-VALIDATOR-001` warns on `Prisma.validator(...)`. The default `prisma-client` generator does not include it; use `satisfies`. The deprecated `prisma-client-js` generator still provides the helper, and this check cannot see the generator.
  - `PRISMA-ADAPTER-001` warns when `new PrismaClient()` has neither `adapter` nor `accelerateUrl`. `datasources` and `datasourceUrl` were removed in Prisma ORM 7.
- The optional `python/legacy` methodology covers standard-library APIs removed in Python 3.15 and APIs scheduled for removal in Python 3.16 and 3.17. A removal denies only when the project's oldest declared Python is already at that release (`requires-python`, `python_requires`, a Pipfile Python version, or, if none of those exist, `.python-version` or `runtime.txt`). An older or undeclared target is not denied for a 3.15 removal. Pending 3.16 and 3.17 APIs warn, and deny once the declared floor reaches that release. Each finding names the replacement. Init still selects `python/quality` only.
- Next.js pack 1.3.0 follows the [Next.js 16 upgrade guide](https://nextjs.org/docs/app/guides/upgrading/version-16). `NEXT-PARAMS-001` and `NEXT-SEGMENT-001` deny synchronous `params` and `searchParams` reads. `NEXT-SITEMAP-001` and `NEXT-IMAGE-001` deny synchronous sitemap and image `id` values. `NEXT-REVALTAG-001` denies `revalidateTag` without a second argument. `NEXT-PROXY-001` denies a named `middleware` export in `proxy.ts`. `NEXT-PROXY-002` warns when `middleware.ts` sets `config.runtime` to `"nodejs"`. Each rule includes the repair and the upgrade-guide link. They run only when the nearest `package.json` declares `next` entirely on 16 or newer, so a Next.js 15 project is not denied.

### Changed
- Scan ignores a language or dependency that appears only under `fixtures/` or `fixture/`, the same way it already ignores a docs site, examples tree, or website folder. A `.svelte` file, `svelte.config.*`, or dependency that appears only there does not select a pack. Evidence in primary source still does.
- The mattpocock pack is reviewed at [mattpocock/skills@4ae2317](https://github.com/mattpocock/skills/commit/4ae2317ddb22b046e26455e4f9c9b3aaaf62212d) (2026-10-31), 26 commits after `6fd947921b935b7e1e69293a200400f0fdd5c15f` (2026-10-06). Pack version `1.1.1`. The seven warning checks stay. Upstream did not drop the sections those checks paraphrase (`tdd` tautologies, relative mocks, call counts, conditional mocks; small function surfaces; tagged `[DEBUG-...]` logs; the Total TypeScript enum companion). The new requirements are workflow or session evidence and are recorded in `packs/mattpocock/INVARIANTS.md`: fresh subagent context, a fresh implementer per ticket, a standards-file search during code review, a diff that proves a forced mutation landed before trusting a red test, a one-line seam note, a fetched ticket title, wayfinder label and research-branch rules, setup and wizard template fixes, and the in-progress `software-factory` and `chief-of-staff` skills. `MP-DEBUG-001` states that the mutation diff is outside the check. The MIT notice in `packs/mattpocock/LICENSE` is unchanged and matches upstream.
- The TypeScript pack is 1.3.0. `typescript/strict-types` is 1.5.0 and `typescript/legacy` is 1.1.0.
- `PRISMA-TXCLIENT-001` now cites the Prisma ORM 7 interactive transactions page. The Prisma ORM 8 transactions page says: "Prisma ORM 8 has no `$transaction`, so both of the Prisma ORM 7 forms become `db.transaction(async (tx) => ...)`." Prisma ORM 8 is still a release candidate. Follow-up rules for that client are in the prisma backlog and are not implemented here.
- `PRISMA-CONNECT-001` tells you to keep one shared client, and on Prisma ORM 7 to construct it with a driver adapter or `accelerateUrl`.
- `NEXT-ASYNC-001` stays a warning on Next.js 15 and earlier, and when the declared `next` range can still install 15 or cannot be read. It denies when that declaration is entirely Next.js 16 or newer, including 16 prereleases.
- The Next.js pack is 1.4.0. These three rules read a literal `cacheComponents: true` from the first existing root `next.config.js`, `next.config.mjs`, or `next.config.ts`. A nested, commented, or computed flag is not treated as enabled. The Next.js 16 removals and their version gates stay. Sources: [Migrating to Cache Components](https://nextjs.org/docs/app/guides/migrating-to-cache-components) and the [route segment config](https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config).
- **`NEXT-CACHE-001` stays off under Cache Components.** The check does not run when `cacheComponents: true`, so a bare `fetch`, including one inside `use cache`, is not reported. In the previous model the default remains `auto no cache` and the rule stays off. Existing `fetch` `cache` and `next` options are not reported; the migration guide says they keep working.
- **`NEXT-REVAL-001` is now deny, and only when `cacheComponents: true`.** Without that flag, `export const revalidate = false` is the documented default and is not reported. With the flag, an exported `revalidate` on a page, layout, or route is denied, including `false`, `0`, and a positive number. Remove it and use `cacheLife` inside `use cache`, or leave the data uncached.
- **`NEXT-SERVER-EXPORT-001` newly denies server-file exports when Cache Components is on.** It still denies route segment exports from a `'use client'` page, layout, or route, and that list now includes `dynamicParams` and `fetchCache`. With `cacheComponents: true` it also denies server exports of `dynamic`, `dynamicParams`, `fetchCache`, and `runtime`, including `runtime = "nodejs"`. `preferredRegion`, `maxDuration`, `generateStaticParams`, `ensureStatic`, and `instant` are not flagged on the server.

### Fixed
- `JS-EVAL-001` flags indirect `eval`. A comma expression that yields `eval` was missed, including `(0, eval)(code)`, `(1, eval)(code)`, and `(void 0, eval)(code)`. `globalThis.eval(code)` and `window.eval(code)` stay flagged. A name that only contains those letters, such as `evaluate(code)` or `item.evaluate(code)`, is not. The javascript pack is 1.2.1 and `javascript/safety/no-eval-call` is 1.0.1.
- `pregate scan` recommends the Svelte pack (`svelte/runes` and `svelte/stores`, catalog `svelte@1.2.0`) when a project is Svelte. Exact `svelte` dependencies and peer dependencies are confined to the package that declares them, the same way Vue declarations are. `@sveltejs/*` dependencies and peer dependencies count too. The Svelte repository is the package named `svelte` and does not depend on `svelte`, so that package name counts. A `.svelte` source file or a `svelte.config.*` file counts as well; those files do not add a package owner. A devDependency and a similarly named package, such as `eslint-plugin-svelte`, do not.
- Scan and guide no longer recommend a pack from evidence that lives only in a docs site, examples tree, or website folder. Folder names `doc`, `docs`, `documentation`, `website`, `example`, `examples`, `sample`, `samples`, `demo`, `demos`, and `playground` are ignored at any depth, including `packages/docs`. Evidence only under `.github/`, or only in a `scripts/` directory of at most three inventoried files, is ignored the same way. A `.svelte` file, `svelte.config.*`, or Svelte dependency that appears only in those folders does not select the Svelte pack. A Next.js or React dependency in the root `package.json` or in a primary app package such as `apps/web`, a primary Svelte app, and Python source or project metadata outside those folders, still recommends that pack.

## [0.0.3] - 2026-11-03

What changed for people installing or gating a repository. **Windows users of 0.0.2 should upgrade.** Two bugs on that release could let an edit through on Windows without a finding. Notes: [0.0.3](docs/releases/0.0.3.md). The previous public tag is [v0.0.2](https://github.com/pedroknigge/pregate/releases/tag/v0.0.2).

### Added
- Pack precision on a pinned set of public repositories, one or more for each parsed language. `scripts/bench-audit-repos.ts --precision` counts findings per pack. Sample precision is published only for the maintainer-labeled packs in `bench/labels/`. Packs with no labels stay unmeasured. The method and the limits are in `docs/guides/rule-precision.md`.
- CI measures the compiled Pre hook on 200-line and 2,000-line files on Linux, macOS, and Windows. The required check stays `bench` on `ubuntu-latest`; macOS and Windows run the same gate. Each route's baseline is the median of eight hosted median p95s. The gate fails when a new median is more than 55% above that. The widest run in that sample was 44.7% above its median, and the extra 10 points keep a repeat of that slow run inside the limit.
- When Git cannot be used, Pregate still denies the edit and names the failure. `git-missing` means `git` is not on PATH (install Git). `git-not-repository` means this directory is not a Git repository, or its `.git` was removed (`git init`, or restore `.git`; a scratch directory can be left with `pregate disable`). `git-error` means Git ran and returned some other error (`git status`, or `pregate disable` for a scratch directory).

### Changed
- Codex 0.166.0 is the verified CLI. For Bash, `PreToolUse` `cwd` is the command's resolved working directory ([openai/codex#57198](https://github.com/openai/codex/pull/57198); permission and post-tool hooks do the same in [#57203](https://github.com/openai/codex/pull/57203)). Relative shell paths resolve against that directory. A working directory in a subfolder still uses the same project root. A working directory outside the repository does not drop that project's gate, and a write that lands in the session project is still judged by that project's contract rather than by another project's. `apply_patch`, `SessionStart`, and `Stop` still carry the session directory. The payload has no version field and the same shape as 0.159.2, so 0.166.0 is the minimum supported Codex release.
- The README states the platforms this release actually supports: macOS ARM64 is stable, and Linux and Windows are experimental. It summarizes what a global setup writes, how `disable` and `uninstall` remove it, and that advisor mode or the GitHub Action is the way to start. The install guide remains the place for checksums, signatures, and updates.
- Each release archive carries the GNU Library General Public License, version 2, for the JavaScriptCore that the Bun 1.4.4 runtime links statically, and the full GNU Lesser General Public License, version 2.1, for tinycc. The notice gives permanent links to the Bun tag `bun-v1.4.4`, WebKit commit `d6375c72affe0f70222cdcb45012b10f0bf3a9d5`, and tinycc commit `05f0fafaa3be31e31d7b4b5c17dc60f62c991171`, plus the steps to rebuild. Setup copies that notice next to the installed engine.

### Fixed
- **Windows: an unaccepted preset made the hook skip the edit.** On Windows, `git add` rewrites the preset's timestamp, and the file clock can sit ahead of the hook. Pregate then treated the project as if it had no contract. The pre-edit hook exited successfully and recorded nothing, so the edit was allowed. 0.0.3 denies that call (`lock-stale`) and says to commit the preset and open a new session. The edit does not land silently.
- **Windows: an 8.3 short path and its long path looked like different projects.** Windows sometimes reports a short name such as `C:\Users\ME~1\...` and sometimes the long name. Consent stored under one spelling did not match the other, so a project you had agreed to protect looked unconsented and the hook exited without a finding. 0.0.3 treats those spellings as the same directory, by the file's identity rather than the letters in the path.
- Inside an enabled root, a shell, interpreter, or `make` command whose script is not a literal path is denied (`bash "$SCRIPT"`, `sh "$X"`, `bash < "$S"`, `python3 "$P"`, `node "$P"`, `make -f "$F"`, `powershell -File $P`). A bare command name is resolved on `PATH` and scanned when that file is a script. The denial says why and how to name the script literally. Concatenation and encodings the decoder does not recognize stay residual limits.
- Catches on the trust path no longer hide an unexpected error. A read or parse failure that is not the expected kind propagates, so the hook denies it. A catch that still handles every error says why that fallback is fail-closed, and CI rejects a new unannotated catch-all in `src/`.
- Living docs, the skill, and installer messages name 0.0.3. They do not send readers to pre-rename versions, private-repository downloads, or release files this repository does not publish.

## [0.0.2] - 2026-11-02

What changed for people installing or gating a repository. The first public tag remains [0.0.1](docs/releases/0.0.1.md).

### Added
- Pre hooks reuse a compiled lock when the contract and this build are unchanged. Admission still compares that compiler output with the lock bytes, and a corrupt cache is recompiled.
- Release archives and `SHA256SUMS` are signed with keyless cosign (GitHub OIDC). Each signed file is published as a `.bundle`, and the workflow also attests build provenance. Installers and the GitHub Action refuse a checksum or signature that does not match. Set `require-signature: false` only for a release that was cut before signing.
- The no-new ratchet keeps debt that moved with an unchanged function body, and still treats a copy sitting next to the original as new debt. A symlink is judged by the path you spelled: a target in another enabled root is that root's problem, and a target in no enabled root is denied.
- `docs/guarantees.md` records, from an adversarial end-to-end run, where each ratchet and trust-boundary case is sound, best-effort, or still a gap.
- A findings count for each bundled pack against pinned repositories. Unlabeled findings stay unlabeled. The report does not turn them into a false-positive rate.
- The GitHub Action has a default for each mode. `check` scans the whole tree. `audit` no longer receives `--all` (that flag is a usage error). `ratchet` requires `base` and stops before it can fall through to a full check. A SARIF path follows the same rules.
- CI, release, native-release, the bootstrap jobs, `action.yml`, and the generated consumer workflow pin every GitHub action to a full commit SHA with a `# vX` comment. A lint fails if one is unpinned.
- The generated CI workflow reads the engine version from the base branch lock and verifies the cosign bundles before it unpacks the binary.

### Changed
- The default TypeScript contract was recalibrated against mature repositories. Some findings that used to deny are now warnings. A project that needs the old hard stop opts that rule into deny.
- Hook pre denies more ways around control commands: inline interpreters, scripts fed on stdin, scripts with no suffix, Makefiles, and edits of user-level harness settings. `pregate approve` applies only after a person confirms it on a terminal.
- There is still no npm package. Install from the GitHub release. The README and install guide say so.
- The Action's default version is 0.0.2, the release this tree publishes. `scripts/build.ts` refuses to pack installers or an Action whose version disagrees with `package.json`. The previous default asked for v0.0.1 signature bundles that were not published.
- Signing tests stay offline unless `PREGATE_E2E_SIGSTORE=1`. CI sets that and uses real cosign. A local `bun test` does not download cosign or contact Sigstore.
- Docs generation sorts the same way on every machine. Bench and smoke approve `enable` at a terminal, so they do not skip the human gate. Stdout and stderr finish writing when the pipe is non-blocking, which matters for hook decisions on Windows and in CI.
- On Windows, setup waits for an on-access scanner to release a new `pregate.exe` before renaming it into place. Ordinary atomic writes use that same retry. A lock that outlasts the wait still fails.
- `node_modules` is not tracked.
- **Action needed for unattended jobs:** `CI` in the environment no longer approves anything. Tools and agent sessions set `CI` too, so it was never a safe signal that nobody was at the keyboard. A job that really runs without a person (for example, one that calls `pregate enable --yes` or `uninstall --yes`) now sets `PREGATE_UNATTENDED_APPROVAL=1` itself. The shell guard denies an agent command that sets it.
- Development, CI, and release jobs install Bun 1.4.4 from `.bun-version`. Bun 1.4.2 can segfault while leaving `bun test --isolate` after the tests have passed ([oven-sh/bun#43056](https://github.com/oven-sh/bun/issues/43056)); that crash is fixed in 1.4.3 and later. The Windows suite is the job that runs with `--isolate`. GitHub Actions stay pinned to a full commit SHA.

### Fixed
- A compiled-lock cache write no longer drops every error in an empty `catch`. A filesystem failure leaves the cache unwritten and admission stands, so the next hook recompiles. Any other error propagates.
- Terminal approval reads `/dev/tty` directly. Bun 1.4.4 pauses stdin when a readline stream on that device is destroyed, so the next question never saw what was typed.
- Looking up the project that started a hook no longer drops every error in an empty `catch`. A path with no existing ancestor is still not a project. A symlink loop or any other error propagates.
- The two known symlink gaps stay skipped, and they are not a passing attack. They use `test.skipIf` until `PREGATE_RUN_KNOWN_GAPS` is set, so `check --all` no longer sees an unconditional `test.skip`.

Thank you to the pre-release reviewers who found these trust-boundary holes. Each one now has an end-to-end test that runs the compiled binary.
- **Loosening the contract needs a person.** Before this fix, a short script could switch rules to `advisor` and run `pregate preset compile`, and every check accepted the result. Now:
  - `check --ratchet` compares the base lock with the head lock and fails on any loosening. It prints a digest for that exact change. A maintainer accepts it by putting the digest in the repository variable `PREGATE_ACCEPT_CONTRACT`, which a pull request cannot edit. The Action has a matching `accept-contract` input. Protect `.pregate/` and `.github/workflows/` with CODEOWNERS so a pull request cannot rewrite the check either.
  - Stop and the pre-commit hook block a looser lock unless this machine recorded a person approving that exact lock. These local records help, but the same user can forge them. CI is the boundary.
  - `preset compile` asks a person before it writes a looser lock.
  - Scripts that run `preset compile`/`apply`, `init` or `promote` without `--preview`, `feedback apply`, `storage apply` or `issue submit` count as control commands, like `approve` and `disable` already did.
- **Removing consent is no longer silent.** If consent for a project is disabled or deleted mid-session, Stop warns and names the project, and `pregate status` warns for a day. This works on Linux, macOS and Windows, even when every consent record is gone.
- **Git history commands are writes.** `reset --hard`, `checkout <commit>`, `switch --detach`, `stash`, `clean -f`, `cherry-pick`, `revert`, `read-tree` and `checkout-index` are judged by the files Git says they would change. They are denied when they would change `.pregate/`.
- **Agents cannot approve through a native permission prompt.** Every harness denies an approval command the agent issues and tells the person what to type: `! pregate approve <code>` in Claude Code, Codex, Grok and agy, or a separate terminal in Cursor.
- **The control-command scan is harder to dodge.** It joins lines split with `\`, a backtick or `^`, reads the whole script instead of stopping at 1 MiB (anything over 64 MiB is refused), and decodes UTF-16 and UTF-32 scripts such as Windows PowerShell files. Inline Python, Node, Bun, Deno, Perl, Ruby and PHP code is judged by the write calls it makes, not by whether an argument looks like a file name.
- `docs/guarantees.md` and `SECURITY.md` now say exactly which of these protections are enforced in CI, which are best-effort on a local machine, and which detect tampering rather than prevent it.

## [0.0.1] - 2026-11-01

Initial public open-source release of **Pregate** (`v0.0.1`, core `0.0.1`).

### Added
- **Multi-Harness Pre-Execution Gate**: Intercepts `Write`, `Edit`, `MultiEdit`, `Bash`, and `Stop` events across **Claude Code**, **Cursor**, **Codex**, **Grok**, and **Antigravity (`agy`)**, plus Git `pre-commit` and CI gates (`pregate check`).
- **Multi-Language Static & Architectural Analysis**:
  - TypeScript / JavaScript (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`)
  - Vue and Svelte Single-File Components (`.vue`, `.svelte` `<script>` block extraction with exact line/column offset preservation)
  - Python (`.py`) via bundled WebAssembly Tree-sitter grammar
  - Go (`.go`) via bundled WebAssembly Tree-sitter grammar
  - Rust (`.rs`) via bundled WebAssembly Tree-sitter grammar
- **Architectural & Production-Readiness Catalog**:
  - **68** built-in core checks across **2** core methodologies (`core/pregate-integrity` and `core/software-invariants`).
  - **44** bundled optional packs providing **1,028** optional checks (**1,096** total checks across languages, architecture, frameworks, data, auth, and cloud).
- **Digest-Bound Human Approval & Protected Governance**:
  - `.pregate/preset.json` and `.pregate/pregate.lock.json` contract compilation with SHA-256 digest-bound human previews (`pregate approve <code>`) and shell-command guards.
- **Debt Ratchet, Advisor Mode & Repository Audit**:
  - Zero-friction `advisor` mode, `pregate promote` to graduate clean rules to `enforce`, and `pregate check --ratchet --base <ref>` to block new debt while allowing incremental cleanup of existing baselines.
  - `pregate audit` and `pregate fitness` to verify architectural layers, invariants, and bounded behavioral fitness tests.
