# Release 0.0.15

**Pregate** `v0.0.15`, core `0.0.1`. macOS ARM64 stays the stable platform. Linux and Windows archives stay experimental until native validation is recorded.

Install 0.0.15 with `pregate update`. If you come from 0.0.13 or older, also run `pregate setup` once. No project needs a step.

This release fixes what the first real session on 0.0.14 showed. Nothing blocked the end of a turn in that session, and the agent still handed commands to the user: a check that asked for a digest, a check the agent was not allowed to run, and git commands it did not try.

## A plain check does not refuse a looser contract

`pregate check` with an uncommitted contract change exited 1 with `PREGATE DENY contract-loosened` and asked for `PREGATE_ACCEPT_CONTRACT=<digest>`. That was the local digest step 0.0.14 meant to remove.

A plain `pregate check` now prints the `contract-loosened` note and judges the rules, as the pre-commit check does. Only `pregate check --ratchet --base <sha>`, which CI runs, refuses a looser contract.

## A contract change no longer reviews every importer

A change to `.pregate/preset.json` or `.pregate/pregate.lock.json` started the dependency review of the whole project, because any changed JSON file may be a resolver configuration. No resolver reads those two files, so that review could find nothing.

In a project of 23,000 files, `pregate check` after a contract change took 2 minutes 27 seconds. It now takes 2.5 seconds. Stop and the pre-commit check take the same path.

## The agent runs the check and git itself

The shell guard allowed the launcher's absolute path only for `check --stdin`. A plain `<launcher> check` was denied as `protected-path`, and hook messages cite that path, so an agent that followed them was denied. Every read-only pregate command now runs by that path, including `check`, `check --all`, and `status --verbose`.

The `/pregate` skill now says that git is the agent's to run: commit, merge, pull, push, and switch branches, including `git add` and `git commit` of `.pregate/` files the user changed or approved. The guard already allowed these. The earlier text led an agent to hand them to the user.

## Also in this release

`pregate doctor` no longer says that a newer harness version may cause `payload-unrecognized` denials. Since 0.0.14 such a call passes with a note.

The real-repository evidence script reads the 0.0.14 status text, and its replay expects what 0.0.13 and 0.0.14 ship: a `git commit --no-verify` without Pregate's git hook, `pregate pack enable --yes`, and an inline Node write are allowed.

## What this release does not establish

- A change to another file still starts the dependency review, and a change to a JSON file that could be a resolver configuration reviews every importer. Only the contract pair is excluded.
- A repository without CI that runs `pregate check --ratchet` has only notes locally. Nothing holds a loosened contract there.
- `pregate disable` still asks for `y` on a terminal.
- The full suite does not run on macOS in CI. macOS runs the latency and release-build jobs there, and the suite on the maintainer's machine. Linux and Windows archives stay experimental until native validation is recorded.

The [changelog](../../CHANGELOG.md) lists every change.
