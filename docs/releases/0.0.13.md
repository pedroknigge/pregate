# Release 0.0.13

**Pregate** `v0.0.13`, core `0.0.1`. macOS ARM64 stays the stable platform. Linux and Windows archives stay experimental until native validation is recorded.

Install 0.0.13, then review the project update it prepares (`pregate update --project --preview`) and approve that exact digest. A global update prepares that review for each enabled project whose lock still pins an older engine.

If you installed Pregate globally, with `install.sh`, `install.ps1`, `npm i -g pregate`, or `npx pregate`, update that installation so the hooks use 0.0.13. Run `pregate update`. It installs this engine and prepares a review for each enabled project that still pins an older one. Approve that review before the project runs on 0.0.13. A hook keeps using the engine the project already pinned until that review is approved.

This release is for a project that already ran `pregate enable`. The shell guard stops blocking ordinary work, enable and audit can leave noisy folders out of analysis, three rules stop flagging code that was fine, and five packs pick up current advisories. A directory that was never enabled, and a checkout that was disabled, block nothing. No rule was removed or downgraded.

## The shell guard stays on Pregate's own files

Inside a project you enabled, the shell guard blocks a command that acts on Pregate itself (#154).

It still denies:

- a write under `.pregate/`, or of the contract, config, lock, or baseline
- a write of a harness file that holds Pregate's hook entry
- forging an approval, by setting `PREGATE_UNATTENDED_APPROVAL` or the other approval variables
- `pregate enable` and `pregate disable`, including `--yes`. Those stay on a separate terminal. A script or wrapper of either is still denied.

It allows the rest of a normal session, including a harness `!` line:

- `git checkout` and `git switch`. A change those commands would make under `.pregate/` is still denied.
- package scripts, such as `pnpm`
- a shell write to source, such as writing a source file from the shell. Write and Edit still check that source.
- `pregate approve --yes`, with an optional `--digest`. A bare `pregate approve` still asks for `y` on a terminal.

An agent can run that approval command. The approval log records a non-terminal confirmation (`via: "yes"`). In an interactive Claude Code parent session, and in an interactive agy session, the hook asks before the command runs. Accept runs it. Reject runs nothing.

## Folders that produce false positives

`pregate enable` reads the tree and proposes folders that usually produce false positives (#155): vendored trees, generated output, dependency directories, fixtures and snapshots, minified bundles, git submodules, and directories named by `.gitignore`. Each candidate includes a reason and the evidence.

You accept them with the same review as any other contract change: typed `y`, or `pregate approve <code>`. Accepted folders are appended to `scope.exclude`. `CI` alone does not accept them. A folder the layer map names, and Pregate's own contract and protected paths, are never proposed.

`pregate audit` repeats the scan and lists only folders that are not already excluded. It prepares a review you accept with `pregate approve --yes --digest <sha>` from the harness shell. Audit does not change the contract, and it does not ask you to run `pregate enable`.

`check`, the pre-write gate, and audit skip an excluded folder. Leaving a folder out of analysis is not permission to hide an edit there: placement still denies creating or editing a file in that folder.

## Three false positives

`DRIZ-RAW-001` no longer flags a plus that only builds a value inside a `sql` template parameter, such as a string joined with an id and passed to `.execute` (#160). Drizzle binds that interpolation. A plus that builds the SQL text passed to `.execute` still flags, and any `sql.raw` call still flags. The drizzle pack and `drizzle/queries` are 1.3.1.

`NEXT-SEGMENT-001` no longer flags `params` inside `defineRoute`, which awaits the segment Promise before the handler, or a `params` binding destructured from `await` (#162). A route that reads the Promise directly still denies. The Next.js pack is 1.5.1.

`architecture/CA-DEP-002` no longer denies `import { NextResponse } from 'next/server'` in a Next.js delivery file (#163): an App Router `route`, `page`, `layout`, and the other delivery files, a Pages API route, and `middleware` or `proxy`. A file in a core layer such as `src/core` or `src/domain` is still denied, including through `next/server`. An `app` folder that imports `next` or `next/*` is detected as an adapter. `architecture/clean-architecture` is 1.0.2 and the architecture pack is 1.4.1.

## Pack refreshes

These rules run only where `pregate enable` is in effect and the methodology is selected.

The Next.js pack is 1.5.0 and adds `NEXT-PIN-001` on `nextjs/rendering` (#152). It warns when `package.json` or a lockfile can install `next` at 15.5.28 or older, or from 16.0.0 up to but not including 16.4.5. The patched releases are 15.5.29 and 16.4.5. A range entirely on a patched release stays quiet. The false-positive fix above is 1.5.1, on top of that pin.

The tRPC pack is 1.3.0. `TRPC-PIN-001` on `trpc/router` warns when `@trpc/server` is pinned at 11.0.0 or newer and below 11.29.11 (#149). A pin below 11.0.0, a pin at 11.29.11 or newer, and an unreadable spec stay quiet.

The Nuxt pack is 1.3.0 and adds `nuxt/security` (#153). That methodology is not part of a bundled preset. Select it with `pregate pack enable nuxt/security`. `NUXT-PIN-001` warns when `nuxt` is pinned at 3.0.0 or newer and below 4.7.0. Nuxt 3 has no patched line; the upgrade is nuxt 4.7.0 or newer. `NUXT-RULES-001` warns on a cache rule that can still install a version below 4.7.0. `NUXT-BUILDER-001` warns on `builder: 'rspack'` once `nuxt` is 4.7.0 or newer.

MongoDB pack 1.3.1 raises the `MONGO-OIDC-002` floor from 7.9.0 to 7.9.1 (#150). A pin of `mongodb` at 7.9.0 now warns. A pin of 7.9.1 or newer does not. The window still opens at 6.7.0. `MONGO-OIDC-001` still requires one OIDC mechanism and mongodb 7.9.0 or newer. The warning runs where `mongodb/models` is selected.

The pstack pack is 1.2.1 (#151). PS-63 no longer names the Orchestrate playbook. PS-60 follows the shortened Babysit playbook. PS-68 follows the shortened Multi-phase plan. Rule ids, severities, and receipt fixtures are unchanged. The obligations still run only where `pstack/playbooks` is selected.

## Also in this release

Inside a project you enabled, a call this version cannot classify now denies: a payload it cannot read, a missing or stale lock, an edit it cannot reconstruct, and shell syntax it cannot finish. The first line leads with the repair. A preset may set `"uncertainty": "open"` to let only those unclassified calls through, after `pregate preset compile`. That does not turn rule violations or protected paths off. A directory that never ran `pregate enable`, and one that ran `pregate disable`, still allows.

A deny names where the code should go and what to use instead, when the rule declares that.

Claude Code 2.1.295 and newer denies a PreToolUse hook that crashes, times out, or returns invalid output, where the project is enabled. `pregate doctor` warns when the installed Claude Code is older than that. OpenCode 2.4.0 judges each tool call inside a Code Mode script on its own.

The node pack is 1.5.0. `NODE-PIN-001` warns when an exact Node.js pin is below the patched release for its line: 22.23.5, 24.22.3, or 26.13.1. NestJS pack 1.3.0 adds the opt-in methodology `nestjs/transport`. Select it with `pregate pack enable nestjs/transport`. It is not added to existing presets.

On Windows, a supervised Pre gives the engine its full 5 seconds after the engine has the input. A clean `git switch` is no longer denied because the cold start used up the deadline.

## What this release does not establish

- No rule was disabled, downgraded, or removed. Timeouts, thresholds, and the committed latency baselines are unchanged. The macOS latency gate still compares each route with v0.0.12 measured on the same runner.
- `pregate enable` and `pregate disable` are still human commands. The shell guard denies them from the harness.
- An exclusion is a proposal until you approve that digest. Audit does not write the contract.
- A shell write to source is allowed. The edit tools still gate that source. A write under `.pregate/` is still denied.
- `nuxt/security` and `nestjs/transport` are not part of a bundled preset. Select one with `pregate pack enable`.
- The full suite does not run on macOS in CI. macOS runs the latency and release-build jobs there, and the suite on the maintainer's machine. Linux and Windows archives stay experimental until native validation is recorded.
