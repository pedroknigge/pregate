# Release 0.0.6

**Pregate** `v0.0.6`, core `0.0.1`. macOS ARM64 stays the stable platform. Linux and Windows archives stay experimental until native validation is recorded.

Install 0.0.6, then review the project update it prepares (`pregate update --project --preview`) and approve that exact digest. A global update prepares that review for each enabled project whose lock still pins an older engine.

0.0.5 added the path from an instruction file to rules. This release is what the first trial of that path on a production repository changed. The trial is published as a [case study](../benchmarks/case-study-production-repository.md), with what it measured and what it did not.

## No folder outside the layer rules

A file in no layer is unrestricted. With a partial layer map, code moved to an uncovered folder imported anything and the check stayed quiet, while the same import from a declared layer was reported.

- `pregate layers apply <map.json> --preview --complete` refuses a map that leaves a source file in scope in no layer, or under which a folder created later would be in none, and names the folders.
- A catch-all layer such as `src/**` closes the gap. The most specific layer path still wins, so it takes only the files no other layer names.
- Partial maps are unchanged, and so are the engine and the contract format. Completeness is a property of the map, and it is opt-in.

## Rules from prose, with their exceptions

- A `compile apply` proposal can state where the code is allowed with `except`, a list of globs. The drafted rule ignores those paths, and the engine proves it before staging: the failing code placed under each excepted path must pass.
- A first layer map, or new layers beside existing ones, no longer prints `WARNING: this may weaken protection` when the new globs share a path prefix. A new glob that can take a file from a layer that already had it still warns.

In the trial, one rule made from a statement about money was exact as a pattern and broader than the statement: 5 of 15 sampled findings were money, and 8 were hours, a coordinate or a percentage. A rule like that needs a path scope or stays in advisor mode. The case study has the sample.

## A large file no longer stalls analysis

One vendored 1.9 MB, 68,000-line JavaScript bundle made an audit run for more than ten minutes. Three questions with one answer per node were asked again for every candidate. Each is now answered once per node, and findings are unchanged.

| On an Apple M5 Pro, engine run from source | Before | After |
| --- | --- | --- |
| Check of that file, 194 rules | not finished at 120 s | 7.2 s |
| Audit of the 13,499-file repository | not finished at 600 s | 86 s |

## Clearer first run and audit

- First-run instructions name one command, `pregate guide --preview`. It already proposed advisor mode for a new project; the setup notice, `status`, the setup messages, the README and the skill no longer add `--enforcement advisor`. An end-to-end test covers the path: no mode flag, an advisor finding that does not block the write, promotion, then the same edit denied.
- The human output of `pregate audit` ends with a line that states the exit code of that run and what it means. `Exit 2` is an incomplete audit, not a count of violations, and the line names the cause. Exit codes are unchanged.

## Also in this release

- The architecture notes state the CI latency gate as it runs: the 150 ms budget belongs to the reference machine, and CI fails on a regression against each platform's baseline.
- Windows CI: every temporary directory cleanup in the suites waits out the lock Windows keeps on a just-run engine, and a test with no deadline of its own gets 20 s there.

## What this release does not establish

- No live agent session was measured. The case study has no count of edits stopped before a pull request.
- One rule's findings were sampled. There is no false-positive rate.
- The latency in the case study is the pre-check command run from source, not the registered hook with the compiled engine.
