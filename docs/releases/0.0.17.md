# Release 0.0.17

**Pregate** `v0.0.17`, core `0.0.1`. macOS ARM64 stays the stable platform. Linux and Windows archives stay experimental until native validation is recorded.

Install 0.0.17 with `pregate update`. If you come from 0.0.13 or older, also run `pregate setup` once. No project needs a step.

0.0.16 was released on GitHub and was not published to npm. This version carries all of its changes: monorepo import resolution, a smaller shell guard, packs marked by measured precision, and the engine fixes from a code review. See the [0.0.16 notes](0.0.16.md).

## `pregate update` stops after the engine

`pregate update` installed the new engine in seconds and then prepared a review for every registered project and worktree. On a machine with 77 of them it ran for more than ten minutes at full CPU. Those reviews were not needed: since 0.0.14 any engine reads any project's contract.

A global update now installs the engine, runs setup, and prints one line: projects need no step. Nothing is prepared and no project file changes.

`pregate update --project --preview` still prepares the review that moves one project's committed pins to the installed engine, when you want the lock file to name it.

## Checked and left as it is

The guided setup proposes the project's language methodologies (`typescript/strict-types`, `typescript/anti-evasion`, `python/quality`, `rust/quality`). None of the rules that measured worst in 0.0.16 (`TS-THROW-001`, `TS-FLOAT-001`, `TS-CONST-001`, `EX-STATUS-001`, `VP-CONSOLE-001`) is in those methodologies, so the default proposal is unchanged. The measurement did not cover those methodologies on their own.

## What this release does not establish

- The limits listed in the [0.0.16 notes](0.0.16.md) still apply.
- The full suite does not run on macOS in CI. macOS runs the latency and release-build jobs there, and the suite on the maintainer's machine. Linux and Windows archives stay experimental until native validation is recorded.

The [changelog](../../CHANGELOG.md) lists every change.
