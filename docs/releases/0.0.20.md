# Release 0.0.20

**Pregate** `v0.0.20`, core `0.0.1`. macOS ARM64 stays the stable platform. Linux and Windows archives stay experimental until native validation is recorded.

Install 0.0.20 with `pregate update`. No project needs a step.

## Doctor canary gating

This patch release stops `pregate doctor` from running runtime canaries that cannot pass:

- **Canary runs only where a registration exists:** the canary exercises the registered command through `$SHELL -c`. On a machine whose harnesses are detected through PATH while `pregate setup` never ran, the call could only reach the missing-launcher fallback, so doctor printed one guaranteed `canary was not denied` error per harness beside the launcher error it already names. One `Runtime canary skipped` line now lists the harnesses whose canary is skipped and names `pregate setup` as what establishes a registration. A registration that exists but is modified, and a launcher that is gone, still run their canary: those are the states the canary is the only proof of.

## What this release does not establish

- The limits listed in the [0.0.19 notes](0.0.19.md) still apply.
- The full suite does not run on macOS in CI. macOS runs the latency and release-build jobs there, and the suite on the maintainer's machine. Linux and Windows archives stay experimental until native validation is recorded.
