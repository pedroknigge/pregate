# Release 0.0.4

**Pregate** `v0.0.4`, core `0.0.1`. macOS ARM64 stays the stable platform. Linux and Windows archives stay experimental until native validation is recorded.

Install 0.0.4, then review the project update it prepares (`pregate update --project --preview`) and approve that exact digest. A global update prepares that review for each enabled project whose lock still pins an older engine.

If you use Windows and you are still on 0.0.2, upgrade. Two bugs in 0.0.2 could let an edit through without a finding. 0.0.3 fixed them, and they stay fixed here. The [0.0.3 notes](0.0.3.md) say what they were.

The library has 48 optional packs. Three of them are new in this release.

## New packs

- **Astro** (1.0.0) checks the TypeScript and JavaScript Astro reads outside a template. The engine does not parse `.astro` files. A content collection with no Zod schema is a warning. On Astro 5 or newer, a collection with no loader is denied; an Astro 4 `type: "content"` collection stays quiet. A client environment variable marked secret is denied, and `output: "server"` with no adapter is denied. Middleware must export named `onRequest`. A lowercase HTTP handler in `src/pages` is denied, and an action with no handler is denied. `pregate scan` recommends the pack when `astro` is a dependency or peer dependency. A devDependency, the package name `astro` by itself, `astro.config.*`, and a `.astro` file do not. Evidence that exists only under a docs site, examples tree, or fixtures directory does not either.
- **TanStack Query** (1.0.0) denies a `queryKey` that is not an array, and denies `new QueryClient()` inside a synchronous component, hook, or `render` method. A module-scope client, a `useState` initializer, and an async function are allowed. Scan recommends the pack from the React, Vue, Solid, Svelte, and Angular Query packages in `dependencies` or `peerDependencies`. A devDependency does not. `@tanstack/query-core` and the devtools packages do not, on their own.
- **Hono** (1.0.0) denies a route handler that is only a name or a method, a class named `*Controller` that takes `Context`, `app.head` and `app.on('HEAD')`, `next()` without `await` in middleware, and that same middleware when it is declared outside `createMiddleware`, `factory.createMiddleware`, `createHandlers`, or an inline `app.use` or route callback. Scan recommends `hono/routing` and `hono/middleware` when a package depends on `hono` or lists it as a peer dependency. A devDependency, the name `hono` by itself, and a package such as `@hono/node-server` do not.

## Rules that follow the version you declared

These stay quiet when the project is still on an older release.

- TypeScript 7. A namespace written with the `module` keyword is reported. It is denied on TypeScript 7.0.0 or newer and a warning on an older or unknown compiler. An ambient module (`declare module "pkg"`) stays allowed. `namespace` itself stays a warning. An import assertion (`assert { type: "json" }`) is denied on TypeScript 7.0.0 or newer. Write `with` instead. The installed `node_modules/typescript` version wins over the range in `package.json`.
- Node.js 26, and only when the project declares Node.js 26 or newer. `ServerResponse.writeHeader` is denied. Imports of the removed `node:_stream_*` modules are denied. `module.register` is a warning. Pins come from `package.json` `engines.node` and `volta.node`, `.nvmrc`, `.node-version`, and `.tool-versions`.
- Prisma ORM 7, and only when the nearest package is on Prisma 7 or newer. A Prisma 6 range stays quiet. `$use` is denied. `Prisma.validator(...)` is a warning. `new PrismaClient()` with neither `adapter` nor `accelerateUrl` is a warning.
- Python 3.15. The optional `python/legacy` methodology denies a standard-library API removed in 3.15 only when the project's oldest declared Python is already at that release. APIs scheduled for removal in 3.16 and 3.17 warn, and deny once the declared floor reaches that release. Init still selects `python/quality` only.
- Next.js 16. Synchronous `params`, `searchParams`, sitemap, and image `id` reads are denied. `revalidateTag` without a second argument is denied. A named `middleware` export in `proxy.ts` is denied. `middleware.ts` that sets `config.runtime` to `"nodejs"` is a warning. The older async-request warning denies when the declared `next` range is entirely 16 or newer, and stays a warning otherwise.
- Cache Components. When the root Next config sets `cacheComponents: true`, a bare `fetch` is not reported, an exported `revalidate` is denied, and server exports of `dynamic`, `dynamicParams`, `fetchCache`, and `runtime` are denied. Without that flag, those cache rules stay as they were.

## Also in this release

- Vercel is a CI provider next to GitHub Actions. `pregate install --ci vercel` writes a build recipe that installs the pinned linux-x64 release and runs the gate before the framework build. `pregate ci detect`, `ci status`, and `ci wait` read GitHub commit statuses. Vercel contexts are `Vercel` and `Vercel – <project>` (Ready passes; Error, Canceled, and a missing status do not). A repository that configures both providers must see both pass. The [Vercel guide](../guides/vercel-ci.md) covers the build command, the cache, and preview versus production.
- `pregate scan` recommends the Svelte pack when a project is Svelte: a `svelte` or `@sveltejs/*` dependency or peer dependency, a package named `svelte`, a `.svelte` file, or `svelte.config.*`. A devDependency and a similarly named package, such as `eslint-plugin-svelte`, do not.
- Scan ignores a language or dependency that appears only under a docs site, examples tree, fixtures tree, or website folder, only under `.github/`, or only in a `scripts/` directory of at most three inventoried files. Evidence in primary source still counts.
- `JS-EVAL-001` flags indirect `eval`, including `(0, eval)(code)`. A name that only contains those letters, such as `evaluate(code)`, is not.
- The mattpocock pack is reviewed at [mattpocock/skills@4ae2317](https://github.com/mattpocock/skills/commit/4ae2317ddb22b046e26455e4f9c9b3aaaf62212d) (2026-10-31). Pack version `1.1.1`. The seven warning checks stay.
- `pregate setup` no longer fails the whole install when one detected harness cannot be wired. Codex that does not confirm hook trust is a warning: `hooks.json` is left unchanged, and the message says to approve the PREGATE hooks in Codex with `/hooks`, then rerun `pregate setup`. Setup exits 0 when at least one harness was wired. It exits 1 when none were, or on a real error.
- The Windows test suite no longer requires `sh` or `python3` on `PATH`, or a clone that already enabled long paths. Python inspection tries `py -3`, then `python`, then `python3`, and does not launch a WindowsApps alias.
- The Windows verifier writes `report.json` when the run starts and again after each step. `finished` stays null until the end, so a killed run still leaves the steps that completed. A step that passes its time limit is recorded as timed out, and its process tree is killed. The run says to expect about an hour and warns when less than 2 GB of memory is free. The [Windows verification guide](../guides/windows-verification.md) is the procedure for this tag.
- `pregate demo` no longer exits when `stat` or `realpath` cannot read a PATH candidate. On Windows the Microsoft Store alias for `python3` is skipped. When none resolves, that language's native checks are reported as not verified, and the Python, Go, and Rust demos still run.
- Windows hook admission uses a warm compiled-lock cache and skips the pack walk when the preset has no path sources. CI compiles the bench engine once per run. The Windows 2,000-line p95 went from about 1046 ms to about 798 ms ([#42](https://github.com/pedroknigge/pregate/pull/42)).

The previous public tag is [0.0.3](https://github.com/pedroknigge/pregate/releases/tag/v0.0.3). The first public tag is [0.0.1](0.0.1.md).

## Install

These commands apply once `v0.0.4` is published. Install a tag that has actually been published, and check the archive against `SHA256SUMS` before you run it. There is no npm package.

macOS and Linux:

```sh
gh release download v0.0.4 --repo pedroknigge/pregate --pattern install.sh --pattern SHA256SUMS
sh install.sh --version 0.0.4
```

Windows PowerShell:

```powershell
$dir = Join-Path $env:TEMP pregate-install
New-Item -ItemType Directory -Force -Path $dir | Out-Null
gh release download v0.0.4 --repo pedroknigge/pregate --pattern install.ps1 --pattern SHA256SUMS --dir $dir
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$dir/install.ps1" -Version 0.0.4
```

The Windows check for this tag is [windows verification](../guides/windows-verification.md). Run it in a plain PowerShell window. The commit to verify is the v0.0.4 tag.
