# Release 0.0.5

**Pregate** `v0.0.5`, core `0.0.1`. macOS ARM64 stays the stable platform. Linux and Windows archives stay experimental until native validation is recorded.

Install 0.0.5, then review the project update it prepares (`pregate update --project --preview`) and approve that exact digest. A global update prepares that review for each enabled project whose lock still pins an older engine.

This release is about one path: from an instruction the agent can skip to a rule that runs before the write. Most people reach it through the `/pregate` skill, which runs the commands below and reports in plain language. The human's only step is the approval.

## An instruction file becomes rules

- `pregate compile <rules.md>` reads a file such as `AGENTS.md` and sorts each statement: it compiles to a rule now, it needs an example, or it stays in the file as guidance. `--preview` stages the rules as one review.
- Real instruction files are paragraphs and tables, so the agent proposes. `pregate compile <rules.md> --template` prints the proposals file to complete, with the steps. `pregate compile apply <proposals.json> --preview` takes a short sentence, code that must fail, code that must pass, an optional AST `pattern`, or a bundled rule id. It stages only the rules that pass the generated cases, and names each refusal.
- `compile apply` refuses a synthesized pattern that is the example's own text. Such a rule passes its cases and misses the same mistake written another way.
- `never import <package>` is a third sentence shape that drafts a rule without code.
- The report names the lines that can leave the file after approval and estimates the tokens that stop loading in every session, at four characters per token. Pregate never edits the instruction file.

Cases prove that a rule separates its examples. They do not prove that it matches every form of the mistake or nothing else. Run `pregate audit` after approval to see what a new rule finds in the real code.

## Layers with evidence

- `pregate guide --preview` says what the proposed layer map finds today: the imports that already break each layer, with an example, and the folders that no layer covers.
- `pregate layers [--json]` prints that evidence. `pregate layers apply <layers.json> --preview` stages a map an agent wrote. It refuses a map whose paths match no file.

## Pregate raises the next step

- SessionStart adds a `Promotion ready` line, at most once a day per project, when advisor rules that were advisor before the last seven days reported no finding over at least 20 checked edits. The human still reviews `pregate promote --preview`.
- `pregate report` adds an `Agent loop` line: denials, denials repaired on the next attempt, advisor findings shown, and advisor findings absent on the same file's next edit. These are observations of the next edit, not proof that the code is right.

## Less noise before you ask for it

- Before a project binds its first fitness verifier, the guide review, the per-pack summary lines and the SessionStart briefing do not count the core requirements that have no verifier. `status --verbose` and `audit` print `Project verification: not adopted`. JSON outputs, `audit --full` and `fitness status` are unchanged.
- `pregate status` and `pregate doctor` lead with what is enforced, what only advises or observes, what is unverified, and which harnesses are gated.

## Fixes

- `pregate guide --preview` and `scan` no longer fail with `@layers:core matches no layer` in a project that depends on `dcouplr` and has no core layer. The methodology that reads the core layer is left out and named.
- The shell guard denies `rsync`, archive extraction, in-place formatters, and literal interpreter or shell scripts whose text reaches the same write sinks.
- Codex CLI 0.167.0 is the minimum supported version. Older versions could skip PreToolUse hooks under Guardian review; `pregate doctor` warns.

## Also in this release

- `pregate prepare [--version <v> | --engine <v>]` downloads and verifies a release archive and installs that engine into the user cache. It registers no hooks.
- The python pack (1.4.0) adds `PY-EXCEPT-002`, an advisory warning for a broad `except` whose body does nothing.
- The installation guide documents the npm launcher (`npm i -g pregate`, `npx pregate`).

## What this release does not establish

- The instruction-file and layer commands were exercised in tests, on a sample project, and in one trial on a production repository in an isolated clone. They were not measured with a live agent over time.
- Statement sorting in `compile` is a text heuristic for TypeScript and JavaScript projects.
- `pregate audit` on that 13,499-file repository did not finish within ten minutes. The cause is not investigated.
