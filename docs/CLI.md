## Approval and effects

`guide --preview --full` expands the compact review. `--custom-from-docs` proposes a local data-only pack from explicit documented requirements during new-project setup; it records source provenance, does not invent project tests and requires the same approval. `guide --preview --packs <ns,ns>` can combine migration with selected additions. Discovery includes the entire catalog and reports historical new/changed packs only when the old immutable engine is available. See [guided workflow](features/guided-project-workflow.md) and [using the pregate skill](guides/pregate-skill.md).

`fitness plan [--candidates <path>] [--json|--template [--auto]]` groups nonpassing requirements and shows project-authored candidate conditions, controls, assumptions and gaps, without execution or compliance claims. The stdout template has empty commands/inputs by default (`--auto` pre-populates candidate test-slice commands, input globs and assertion counts from repository test files) and needs actual reviewed assertions. `fitness bind --candidates <path> [--only <assertion-id,...>] --preview` prepares different commands in one digest review; selected partial-coverage claims cannot be adopted as complete requirements. The candidate manifest joins the reviewed fingerprint. Existing comma-ID `fitness bind` remains available and accepts a freshness budget with `--max-age-ms`; each selected condition must actually be covered. One invalid selection rejects the whole proposal. See [project fitness](features/project-fitness.md).

`session rebase <harness:session-id> --preview` reviews the retained-baseline-to-HEAD diff in a clean committed Git worktree, leaving out files that arrived from a base that existed at session start. Only the human applies its exact digest; original snapshots and events remain. It adopts existing debt, does not prove authorship or fix violations and expires after ten minutes. It counts those arrived files and names committed changes no text diff shows (file mode, symlink, binary bytes). Above 8 MiB of diff it lists each file (status, +/- lines, size), deletions and test changes first and never cut by the 200-file cap, with the `git diff` command to inspect, and the digest binds both sides of every file; above 128 MiB of content it refuses. Changed contract, tree or baseline invalidates it. See [Stop guarantees](features/harness-and-shell-guarantees.md).

The guided coordinator is included in 0.0.2. Bare `pregate` opens it only when stdin and stdout are terminals and CI is unset; redirected no-argument input retains hook auto. `guide --json` inspects project state and recommendations without proposals or consent changes. `guide --preview` prepares one combined candidate with detected scope, selected packs and repeatable local `--custom-pack` paths. Selection flags require preview and cannot mix with `--json` or `--projects`; `--packs none` skips additional optional packs, retaining recipe policy. `guide --projects <path...>` offers one human terminal confirmation of all displayed digests, preflights all candidates, preserves disabled consent and lists later per-project failures for retry. There is no guide --yes. Without a terminal, guide displays next actions; the agent presents choices and prepares a preview, then the human approves its exact digest through the supported route. Successful configuration or activation offers an audit and freeze/repair choices. See [guided workflow](features/guided-project-workflow.md).

`status`, `scan`, `explain`, `preset show`, `preset diagnose`, `preset schema`, `check`, `audit`, `report`, `pack list/show`, `doctor` and `--version` inspect or evaluate. Checks and doctor can create local evaluation/canary state. `audit --incremental` reuses content/dependency-validated file results and resumes checkpoints; `--fresh` bypasses reuse and refreshes the disposable local cache. Default audit remains cold. Both cache options preserve full contract validation, fitness evaluation and coverage/exit codes. Cache JSON reports actual reuse, invalidation, checkpoint outcome and limits; see [incremental auditing](features/whole-project-audit.md#incremental-audits-and-checkpoint-resume). `rules test` executes declarative fixtures, never pack-supplied code.

`demo [--language python|go|rust|all] [--json]` is included; default `all` runs generated samples through the compiled production binary and its isolated launcher. It needs Git. It creates and deletes its own temporary projects, installation, settings and consent, and never accepts a consumer project path. Automated sample approval is not a human approval test. Existing debt is tolerated by no-new, a new dependency is denied before writing, and a valid repair is accepted. Native tools run only if already present; missing tools are explicitly not verified. Core fitness requirements stay unverified. See [the demo guide](guides/demo.md).

Project migration: `update --project --preview` and `pack update --all --preview` use the installed engine to prepare one engine/core/registered-pack review without changing preset, lock or consent. A global update automatically prepares one `update --projects ... --preview` review of every enabled registered project (this machine's consent records, their worktrees and the current project) whose lock pins an older engine; a newer pin is never downgraded. It then removes installed engines that neither the new, previous or running engine nor any registered project or worktree pins; a pruned pin in an unregistered clone fails closed with `pregate update --engine <v>` as its recovery. `update --project --preview` names other registered projects with older pins. `status` prints three lines (protection, mode/version, next step); `status --verbose` prints the full report and `status --json` adds `mode`. `doctor` reports Codex or agy without a binary on PATH as INFO, and `setup` skips registering them. `preset diagnose --json` and `preset schema` remain available for invalid contracts; `preset show --json` reads the editable document without asserting admission. See [availability and limits](features/project-update.md).

`update --projects <path...> [--preview|--yes [--no-commit]]` prepares explicit existing projects from any directory, deduplicating resolved roots. Default is preview. All paths/candidates preflight before application. Human --yes prepares fresh full reviews and applies exactly those per project through the approval path, preserving disabled consent; later failures can leave earlier successful updates. Each applied project is committed as one contract commit (`--no-commit` opts out) and reported on one Updated/Current/Failed line. With two or more reviews, the preview prints one batch code: the human's `! pregate approve <code>` from any directory revalidates every project first and applies none if any changed then; each is then applied and committed on its own like a single approval, and consent never changes. Current contracts are no-ops. This does not download a release. See [multi-project updates](features/project-update.md#update-several-projects-from-one-directory).

`audit --jsonl` streams `start` and per-file finding/error records, then an `end` with exit code and aggregate report without a findings array. No `end` means interrupted/failed; an end with code 2 still means incomplete compliance. Final content/contract and fitness checks remain mandatory. JSONL supports cache flags but rejects `--json` and `--plan`; plans require a complete buffered report. It avoids retaining every finding, not all inventory/cache memory. See [streaming results](features/whole-project-audit.md#streaming-results).

`init --preview`, `preset apply <request.json> --preview` and pack operations with `--preview` prepare a reviewed pending candidate without changing the active contract or consent. Request preview validates the patch and full candidate, displays the diff and binds approval to its digest. Invalid requests preserve any existing pending candidate. Use an absolute request path in Codex because its shell payload does not establish the execution directory. Pack fetching may populate a local cache. Draft commands and `pack init` write local drafts/scaffolds.

Help prints the command reference without a preset, request file, stdin or approval. Each known public command path accepts a trailing `--help` or `-h`, including `preset apply --help`, `check --help`, `update --help`, `pack update --help` and `fitness bind --help`. Output writes remain subject to the shell guard.

`approve`, `enable`, `disable`, `uninstall`, plain `preset apply`, a `preset compile` that writes a looser lock, pack activation, `feedback apply`, `storage apply` and `issue submit` require human approval: stdin must be an interactive terminal and the human types `y` on `/dev/tty` (`CONIN$` on Windows). A pipe, including one that contains `y`, does not qualify. `--yes` skips that question only when `PREGATE_UNATTENDED_APPROVAL=1` is already set in the environment (an unattended CI job; `CI` alone does not count); elsewhere it prints the review and still asks on the terminal. It is not agent authorization. `setup/update/uninstall` change the global installation; `install` adds selected Git/CI backstops. Issue submission publishes to PREGATE's native GitHub repository.

Digest-bound approval: review `pregate approve --preview` (a compact summary: the mode, one line per pack, every loosening or removal, the whole preset diff and every written file; `--full` adds every per-rule change and complete file contents), then let the human run the displayed `pregate approve <code>` (the first 12 hex digits of the digest) in a terminal. A harness `!` line qualifies only when that harness gives the command an interactive stdin; otherwise the human opens a terminal of their own. Approval commits exactly the contract files it wrote (`--no-commit` keeps them uncommitted) and removes the applied and stale requests. Every harness denies an approval command issued by the agent and names the human route: `! pregate approve <code>` in Claude Code, Codex, Grok and agy, a separate terminal in Cursor. With `PREGATE_UNATTENDED_APPROVAL=1`, `--yes` prints the complete review without a terminal question. See [approval routes](features/approval-in-harness.md).

The tested Cursor Shell Mode reaches gated Pre without a trusted human-origin marker. Its digest-bound approval fallback requires a separate human terminal; agent approval remains denied. Claude Code, Codex, Grok and agy have controlled native human `!` observations; those are not actual user consent receipts.

## Evaluation modes and exit codes

`check` compares with HEAD in a Git repository and evaluates the current tree without Git. `--all` evaluates the complete selected tree; `--staged` compares the index with HEAD; `--ratchet --base <sha>` compares against a Git base. `--stdin --path <file>` checks proposed contents read from stdin; the input must be valid UTF-8, at most 16 MiB and reach EOF within five seconds after the engine starts reading. Pre-engine wrapper buffering is outside this deadline. These stdin limits do not limit the whole-project audit size. `--format` accepts `agent` or `sarif`. Evaluation modes are mutually exclusive. Bare `--ratchet` uses the default mode.

`check` returns 0 when no selected finding blocks and 1 when it denies or cannot evaluate. Warnings and ordinary shadow findings do not make it fail. Unbound fitness requirements never block work and are not repeated on every check or Stop; `audit` and `fitness status` list them, and a passing check does not certify them. For adopted bindings, missing/stale/incomplete or failed evidence blocks check and Stop independently of the ratchet. `audit` returns 0 when nothing blocks, 1 for findings that block under live policy (enforce mode, ignoring the ratchet) or failed/unproven adopted assertions, and 2 for invalid arguments or incomplete analysis. `audit --strict` restores the complete-compliance codes: 2 also for unsupported/uncovered files and unverified requirements, and 1 for any finding, including shadow, advisor and warnings. Incomplete evaluation takes priority over findings; inspect JSON fitness, coverage and analysis errors. Other public commands generally use 0 for success and 1 for failure. Hook exit codes are harness-specific.

Local Git commands have a five-second deadline per invocation, including batched object reads. An exceeded deadline terminates the Git process and rejects partial output with an error; it does not select a no-Git inventory or a different revision. This is not a whole-command deadline. Git pack fetching has its separate 60-second clone budget. Hook supervision can terminate the engine earlier within its own budget.

`fitness fingerprint <glob...>` reads verifier files and returns their checksum; use it as the reviewed binding's verificationHash. `fitness status [--json]` reports current project verification without executing commands and returns 1 for failed or unverified requirements. `fitness run <verifier|--all>` executes only command arrays bound in the reviewed preset; `--all` selects adopted bindings of active rules, leaving unbound requirements unverified. It returns 0 when the selected assertions pass, and 1 for a missing selection or nonpassing selected evidence. Timeout is at most 120000 ms. At the configured timeout it forcibly terminates the immediate verifier process, including one that ignores SIGTERM, and rejects its evidence. The engine also terminates the immediate verifier if either output channel exceeds 16 MiB, retaining at most the first 4096 bytes per channel in failure diagnostics. Exactly 16 MiB on each channel together remain valid. Input hashing and contract validation are outside this subprocess timeout; it is not a whole-command deadline or a subprocess-tree sandbox. Changed verifier inputs require a reviewed checksum change before execution. Identical commands/input sets/budgets run once for multiple requirements. Evidence is bound to the current contract and selected input tree; edits/additions/deletions invalidate it. A passing reviewed verifier is bounded evidence, not a general semantic proof. See [project fitness](features/project-fitness.md).

`report` and `feedback list/draft` default to a seven-day window. `--days` accepts a positive finite number up to 36500. Reports are observations; `check --all` or `audit` evaluates current code. `storage prune --older-than` uses the same positive day bound; preview/recover only draft a plan, and apply requires its digest.

`report --json` includes `sessionBaselines` for sessions with observations in the selected window: retained `head`, `currentHead`, `startedWithSession`, `dirtyFiles`, `createdAt` in Unix milliseconds, `status` and `reason`. Legacy capture times stay null; missing/invalid snapshots are disclosed without recreation. Stop retains its session baseline across commits, while CLI check uses HEAD/index/merge-base. A clean CLI check does not clear a Stop finding. The report reads metadata, not snapshot contents, and does not reset history. Legacy events without a root still need readable snapshots for root inference.

`preset compile` validates source fixtures and refreshes the lock; it does not grant local consent or migrate pins. Compilation and update previews report interactive import-review cost. Shadow/warn rules do not initiate unchanged-importer sweeps on Pre/Stop or stdin checks; direct-file observations and audit/commit/CI remain. In this checkout, enforcing dependency review can reuse a disposable persistent cache of exact resolver reads after validating importer content, policy context, dependency content and path identity. Affected importers are evaluated again; findings and passing verdicts are never cached. Missing, invalid or unavailable cache state falls back to fresh resolution. `pack add` registers a source and, in the same review, selects its complete methodologies that compile (skipped ones are named; `--source-only` only registers). `pack enable` selects methodologies/rules and adds a missing bundled source in the same review. `rules add "<sentence>"` selects a matching catalog rule or drafts a project rule with generated fixtures into `.pregate/packs/project`, as one review. `--only` is a comma-separated list of alias IDs. Library update uses the installed engine's bundled source; Git update proposes remote HEAD. Pins never activate automatically.

`scan [--json|--plan]` reads stack/dependency facts and proposes optional packs and custom-rule candidates. Recommendations are advisory; custom candidates are not executable rules. `--plan` emits editable JSON for `pack apply <plan.json> --preview`: library/path/Git sources and selected methodologies enter one validated candidate and one human digest approval. Scan also reports supported source-file scope coverage and can include a proposed `scope` in that same plan, preserving explicit exclusions. Scope coverage does not prove rule or semantic coverage. Conventional layer folders (domain, application, ports, infra, adapters and similar) under any source root suggest the language's architecture methodology; when the project declares no layers, the plan includes `layers` derived from those folders for review. Scan and guide name declared layer paths that match no files, because layer rules check nothing there. Frameworks are suggested from `dependencies` and `peerDependencies`; a `devDependencies` entry only suggests testing when it names a test runner. Existing overrides remain. `pack restore` fetches exact committed Git pins, checks namespace/hash/fixtures and changes no preset, lock or local consent. It does not choose upstream HEAD. See [guided adoption](features/guided-pack-adoption.md).

Fitness bindings can set a positive integer `maxAgeMs`. At that age evidence becomes unverified even on unchanged inputs; future or malformed recording times also fail. Source-only bindings can omit it. Remote drift between runs is not detected: assertions must inspect their declared environment and authenticate external evidence. Optional shadow remains diagnostic; explicitly review enforcing overrides for adopted optional readiness gates.

Contract admission compares the complete canonical lock with compilation of the current preset and sources. Matching version and metadata hashes alone cannot admit changed rules, scope, enforcement or failure policy. An altered/malformed/noncanonical lock is stale; regenerate it with `preset compile`. Admission does not grant consent or passing fitness evidence.

`rules test <dir>` tests that source; without a directory it tests registered path, Git and library sources. `--library` selects one bundled pack. `--fixture` replays a reduced directory or public `repro.json`; it does not certify a full pack.

## Hook protocol entry points

Installation manages `pregate hook pre|stop|session-start|auto [--harness <id>]`. IDs: `claude-code`, `codex`, `cursor`, `grok`, `agy`. Hooks consume valid UTF-8 native JSON on stdin, with a 16 MiB input budget and a five-second EOF deadline inside the engine. Invalid encoding, oversized input and stalled producers are rejected in a known consenting project before version redirection; inactive projects remain inert. Supervisor Pre failures use the selected harness's native denial format. Pre-engine wrapper buffering is outside the read deadline. Redirected no-argument input selects hook auto; empty no-argument input prints a one-line hint and exits 0; interactive human no-argument input opens guide. Without any consent, only SessionStart reaches the engine, for its one-line setup notice. `--supervise` and version-redirect output are internal launcher protocols, not user approval commands.
